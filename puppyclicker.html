Descripción del proyecto

Qué es

PuppyClicker es un juego incremental de navegador al estilo de Cookie Clicker. El jugador hace click sobre un perro para ganar puntos, y cada click muestra una foto de perro aleatoria y una pequeña animación. Con los puntos compra razas, que generan puntos por segundo de forma automática, y mejoras que duplican los puntos por click o la producción de una raza concreta. El progreso se guarda por cuenta de usuario en la base de datos, y un panel lateral va mostrando curiosidades sobre perros.

Qué incluye

  • Mecánicas de juego completas, con 9 razas, del Pug al Shiba, con un precio inicial de 15 a 1.000.000.000 puntos y una producción de 1 a 500.000 puntos por segundo. El precio de cada raza sube un 15 % con cada unidad comprada, y además hay 60 mejoras (6 de click y 6 por raza), cada una de las cuales duplica la producción de su tipo.
  • API REST en Node.js + Express 5 + TypeScript con 10 endpoints (registro, inicio de sesión, click, compra de razas y mejoras, sincronización de puntos y listados) sobre MySQL 8 con mysql2 y consultas parametrizadas.
  • Modelo relacional de 7 tablas diseñado en MySQL Workbench, con tablas intermedias para las razas y mejoras de cada usuario; un script SQL crea el esquema y carga los datos del juego al arrancar el contenedor de la base de datos.
  • Autenticación con JWT (tokens de 12 horas) y contraseñas con bcrypt; las rutas del juego exigen token y toman el usuario del propio token, no de lo que envíe el cliente.
  • La lógica de juego se calcula en el servidor. Precios, multiplicador de click y producción por segundo salen del backend, y cada compra se hace dentro de una transacción con bloqueo de fila.
  • Frontend en React 19 + TypeScript + Vite + React Router con pantallas de inicio de sesión, registro y juego; fotos aleatorias de la API pública dog.ceo al hacer click (como máximo una petición por segundo), animaciones de click, cursores personalizados e iconos para cada raza y mejora.
  • 50 curiosidades sobre perros guardadas en la base de datos, que van rotando en pantalla cada 10 segundos.
  • Docker Compose con tres servicios (frontend, backend y MySQL) en una red propia, volumen persistente para los datos y recarga en caliente durante el desarrollo.
  • Trabajo con Git por ramas de funcionalidad (base de datos, endpoints, lógica de backend, clicker, mejoras…) integradas mediante 8 pull requests.

Decisiones técnicas

Estas son las decisiones técnicas más relevantes del proyecto y el razonamiento detrás de cada una.

  • El servidor es la fuente de verdad. El cliente solo indica qué quiere hacer (un click, comprar una raza o una mejora) y el backend calcula precios, multiplicadores y puntos, así que un jugador no puede darse puntos modificando las peticiones desde el navegador.
  • La producción se calcula por tiempo en el servidor. Cada usuario guarda la marca de tiempo de su última liquidación y el backend suma la producción por cada segundo transcurrido. Entre dos liquidaciones se acumulan como máximo 60 segundos, para que una sesión abandonada no genere horas de producción de golpe, y el contador se reinicia al iniciar sesión, de modo que la producción solo corre mientras se juega.
  • Las compras usan transacciones sobre una conexión dedicada con SELECT … FOR UPDATE. Cada compra cobra primero la producción pendiente y bloquea la fila del usuario hasta el COMMIT, de modo que dos compras simultáneas no pueden gastar los mismos puntos.
  • Las contraseñas se migran sin intervención del usuario. Las cuentas con el formato de hash antiguo se verifican con una comparación de tiempo constante y se vuelven a cifrar con bcrypt en su primer inicio de sesión, sin obligar a nadie a cambiar la contraseña.
  • Los datos del juego viven en la base de datos, no en el código. Razas, mejoras, precios y curiosidades están en tablas MySQL, por lo que ajustar el equilibrio del juego solo requiere cambiar el script SQL, sin tocar el frontend.
  • El entorno es reproducible con Docker Compose. El script SQL se monta en el directorio de inicialización de MySQL, así que la base de datos crea el esquema y carga los datos en el primer arranque, y el código se monta como volumen con recarga en caliente en el frontend (Vite) y en el backend (ts-node-dev).

La aplicación se levanta con un único docker-compose up, que arranca tres contenedores conectados por una red Docker propia, y usa además una API externa para las imágenes.

  • El contenedor frontend (puerto 5173) sirve React 19 + Vite, con navegación entre inicio de sesión, registro y juego mediante React Router.
  • El contenedor backend (puerto 8080) expone la API en Express 5 con TypeScript bajo /api. Un middleware valida el JWT y deja el usuario autenticado en la petición, y la lógica de producción está centralizada en un módulo que comparten los endpoints de click, sincronización y compra.
  • El contenedor db ejecuta MySQL 8 con volumen persistente, y su script de inicialización crea las 7 tablas (Usuario, Edificios, Edificios_has_Usuario, TipoMejora, Mejoras, Usuario_has_Mejoras y Descripciones) y carga los datos del juego.
  • Como servicio externo, la API pública dog.ceo proporciona las fotos aleatorias de perros.

Balance

PuppyClicker es un proyecto pequeño y cerrado. Es un juego completo y jugable de principio a fin, con cuentas de usuario, progreso guardado y la lógica de juego en el servidor, que se levanta con un solo comando gracias a Docker Compose.

Revisión posterior

Al preparar el proyecto para este portfolio lo revisé y corregí los fallos de la versión original. El servidor confiaba en el identificador de usuario y en las cantidades de puntos que enviaba el cliente, las contraseñas se guardaban con SHA-256 y una sal fija y aparecían en los logs, y las transacciones se abrían sobre el pool de conexiones, por lo que no garantizaban nada. La corrección añadió autenticación con JWT, bcrypt con migración de las cuentas existentes, el cálculo de puntos en el servidor y transacciones sobre una conexión dedicada.

Qué haría distinto

Aprovecharía para seguir ampliando el juego con nuevas funcionalidades como música, efectos de sonido, eventos aleatorios y un sistema de reinicio de partida.
